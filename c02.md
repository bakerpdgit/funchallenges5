# The Animal Guess-O-Matic

Can you outsmart an animal expert that only knows two animals? Probably! Your challenge is to turn it into a game that **learns whenever it loses**. Inspired by the classic Animal guessing game, you will practise **functions**, **lists**, **loops**, and updating a **decision tree**.

## Getting started

1. Open `c02.py` and run the starter game. Think of a cat or a dolphin first, then try an animal it cannot guess.
2. Complete the tasks below in order. Run your program after every change.
3. Work with a partner: take turns being the programmer and the player who tries to catch the game out.

The starter code already works. These are challenges to develop it, rather than blanks to fill in. There is more than one correct answer: give your expert its own personality!

## Task 1 — Give your expert some personality

Your expert needs a name, an attitude, and a specialist subject.

- Change the welcome, winning, and losing messages.
- Replace the two starting animals and their question. Make sure the animal on the yes branch (`knowledge[1]`) answers yes to your question!
- Ask for the player's name and include it in the goodbye message.

Will yours be a polite zoo keeper, a dramatic wildlife detective, or an overconfident robot?

**Hint:** The `knowledge` list stores the facts. The main code below the functions handles the welcome and replay loop. Store the player’s name before the loop and use it in the goodbye message afterwards.

**Try it:** Play twice, taking a different branch each time. Can your expert correctly guess both starting animals?

## Task 2 — Make the questions friendlier

At the moment, only exactly `yes` counts as yes. Even `YES` is treated as no!

Improve `ask_yes_no` so it:

- Accepts `yes` or `y`, and `no` or `n`, in any mix of capital and lowercase letters.
- Ignores spaces before and after an answer.
- Keeps asking if the player types something else.
- Returns `True` for yes and `False` for no.

**Hint:** Clean up text with `.strip().lower()`. You can check several accepted answers with `answer in ["yes", "y"]`.

**Another hint:** Put the input inside a `while True` loop. A `return` leaves the function, so valid answers can end the loop naturally. Invalid answers should display a helpful message and go round again.

**Try it:** Enter ` YES `, `n`, an empty answer, and `banana`. The last two should trigger another question, not send you down the no branch. Check the replay question too: improving one function improves every place that calls it.

## Task 3 — Follow the animal trail

Two animals hardly make an expert. Give your game at least **four animals**, with some guesses requiring more than one question.

An animal node looks like this:

```python
["cat"]
```

An animal node is a list with one item. A question node is a list with three items: `[question, yes_branch, no_branch]`. Index `0` holds the question, index `1` holds the yes branch, and index `2` holds the no branch. Either branch can contain another question:

```python
[
    "Can it fly?",
    ["owl"],
    ["fox"],
]
```

Replace an animal node in `knowledge` with a question node like this, then expand your tree further. Choose questions that work for your animals.

Next, change `play_round` so it keeps following branches **until it reaches an animal**, however many questions that takes.

**Hint:** `len(node) == 3` tells you whether the current node is a question. An animal node has length `1`. The starter checks this once with `if`. Which statement would repeat that check?

**Another hint:** `node = node[1]` follows the yes branch; `node = node[2]` follows the no branch. Keep the final guess outside the loop so it only happens when you reach an animal.

**Try it:** Draw your tree on paper and play once for each animal. Check that every animal can be reached. If the game guesses a question as though it were an animal, you have stopped following the tree too soon.

## Task 4 — Teach an old program new tricks

Now for the magic: make the game learn when its guess is wrong.

When the player says no to the final guess:

1. Remember the animal the game guessed.
2. Ask which animal the player was thinking of.
3. Ask for a yes/no question that distinguishes the new animal from the old one.
4. Ask whether the answer to that question is yes for the **new** animal.
5. Replace the current animal node with that question and two animal branches, putting each animal on the correct branch.

For example:

```text
Is your animal a cat? (yes/no) no
What animal were you thinking of? elephant
Give me a question that separates elephant from cat: Does it have a trunk?
For elephant, is the answer yes? (yes/no) yes
Thanks! I've learned a new animal.
```

The next round should follow the existing questions, ask the new question when it reaches that spot, and be able to guess either animal.

**Hint:** Reuse `ask_yes_no` to find out which branch the new animal belongs on. If the answer is no, the old animal belongs on the yes branch.

**The tricky bit:** `node` refers to a list inside your tree. Writing `node = [...]` only points that local variable at a different list; it does not replace the list in the tree. Instead, save the old animal’s name from `node[0]`, then replace the contents of the existing list using `node[:] = [question, yes_branch, no_branch]`. The slice `[:]` means all the items in that list.

**Another hint:** After learning, the changed list should contain three items: the question, a yes branch, and a no branch. Each new branch should be a separate one-item animal list, such as `[old_animal]` or `[new_animal]`.

**Try it:** Teach the game an animal whose answer to your new question is yes, then another whose answer is no. Keep the program running and check that it can still guess the old animals as well as the new ones. Swap with a partner and see how large your animal collection becomes!

## Extension — Give it a long-term memory

Your game remembers new animals during a session, but forgets them when you close it. Save the knowledge tree to `animals.json` and load it when the program starts.

- Save the updated tree after each round.
- Load the saved tree before the first round.
- If no file exists yet, use the starting tree.

**Hint:** Python's built-in `json` module can store nested lists. Look at `json.dump(knowledge, file, indent=2)` for saving and `json.load(file)` for loading. Use `with open(...)` to manage the file, with mode `"w"` to save and `"r"` to load.

**Another hint:** Catch `FileNotFoundError` when loading for the first time. Keep the loaded tree in a variable that you pass to `play_round` and later save, so all three steps use the same tree.

**Try it:** Teach the game a new animal, close the program, and start it again. Does it still remember? For an extra challenge, handle an empty or damaged JSON file with a helpful message too.

## Remember

- Indentation decides which instructions repeat and which happen afterwards.
- Every question needs both a yes branch and a no branch.
- A useful learning question must have opposite answers for the two animals it separates.
- Errors are clues. Read the last line of the error message, fix one thing, and run it again.
- Discuss: does your game understand animals, or is it remembering a route through questions? What happens if a player teaches it something wrong?
